# Модуль 03 — Внедрение зависимостей и логирование

## Дисциплина

**CSE5032 — Разработка веб-сервисов**

## Тема

**Внедрение зависимостей (Dependency Injection) и логирование (Logging)**

## Цель работы

На практике изучить работу Dependency Injection в ASP.NET Core, создание и регистрацию сервисов, внедрение зависимостей через конструктор и использование `ILogger<T>` для логирования событий приложения.

## Описание проекта

В рамках практической работы разработан **ASP.NET Core Web API** для управления списком товаров без использования базы данных.

Данные хранятся в памяти приложения в коллекции `List<Product>`.

Модель товара содержит:

* `Id` — идентификатор товара;
* `Name` — название товара;
* `Price` — цена товара.

В сервисе предусмотрены три начальных товара.

## API

Реализованы следующие методы:

| Метод | Endpoint             | Описание                           |
| ----- | -------------------- | ---------------------------------- |
| GET   | `/api/products`      | Получение всех товаров             |
| GET   | `/api/products/{id}` | Получение товара по идентификатору |

Если товар не найден, API возвращает `404 Not Found`.

## Dependency Injection

Для работы с товарами используются интерфейс `IProductService` и его реализация `ProductService`.

Сервис зарегистрирован в DI-контейнере ASP.NET Core:

```csharp
builder.Services.AddScoped<IProductService, ProductService>();
```

Зависимость `IProductService` внедряется в `ProductsController` через конструктор.

Такой подход уменьшает связанность компонентов и позволяет контроллеру работать с интерфейсом, не завися напрямую от конкретной реализации сервиса.

## Логирование

Для записи событий используется `ILogger<ProductsController>`.

В приложении реализовано логирование:

* получения списка товаров;
* успешного получения товара по ID;
* отсутствия товара.

Для сообщений используются уровни **Information** и **Warning**.

Уровни логирования настраиваются в файле `appsettings.json`.

## Проверка уровней логирования

В ходе работы были проверены уровни:

* Trace;
* Debug;
* Information;
* Warning;
* Error;
* Critical.

Также было проверено изменение минимального уровня логирования с `Information` на `Warning`.

При уровне `Warning` сообщения `Information` перестают отображаться, тогда как `Warning`, `Error` и `Critical` продолжают отображаться.

Контрольные вопросы 

1. Что такое Dependency Injection?
Dependency Injection — это механизм, при котором необходимые объекту зависимости предоставляются извне, а не создаются непосредственно внутри самого объекта.

2. Какую проблему создаёт использование new ProductService() непосредственно в контроллере?
Контроллер становится напрямую связан с конкретной реализацией ProductService. Это усложняет замену сервиса, тестирование и дальнейшее изменение приложения.

3. Для чего нужен интерфейс IProductService?
Интерфейс определяет набор методов сервиса и позволяет контроллеру работать с абстракцией, не завися от конкретной реализации.

4. Что такое Constructor Injection?
Это способ внедрения зависимости через конструктор класса.

5. Зачем регистрировать сервис в Program.cs?
Чтобы DI-контейнер ASP.NET Core знал, какую реализацию необходимо создать при запросе определённого интерфейса.

6. Что делает AddScoped?
AddScoped создаёт один экземпляр зависимости в рамках одного HTTP-запроса. Для следующего запроса будет создан новый экземпляр.

7. Для чего используется ILogger<T>?
ILogger<T> используется для записи сообщений о работе приложения, предупреждений и ошибок.

8. В чём разница между Information, Warning и Error?
Information используется для обычных информационных сообщений, Warning — для потенциальных проблем или нестандартных ситуаций, Error — для ошибок, которые произошли во время выполнения.

9. Для чего используется appsettings.json?
Файл используется для хранения настроек приложения, в том числе уровней логирования.

10. Почему слабосвязанный код проще изменять и тестировать?
Компоненты меньше зависят друг от друга, поэтому отдельные части приложения можно заменять, изменять и тестировать независимо.
